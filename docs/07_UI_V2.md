The user asked for a SheetLink-like *working feel* — dense, colour-coded parameter lists — but with our own look and more capability. Do **not** copy DiRoots' colours, button styles, layout proportions, wording or icons; the mockup is our design.

## 1. Window structure (top → bottom)
1. **Title bar** (custom chrome via `WindowChrome`): logo (DocumentLink glyph), name + version, profile chip (combo + Save / Save as / Import / Delete), background progress chip ("Ready" / "Reading values 42 %"), light/dark toggle, Help.
2. **Tabs**: Model · Annotation · Elements · Schedules · Spatial · Panels (v2, hidden until implemented) · **Preview / Edit**.
   - Count badge = number of checked sources on that tab.
   - ★ = user's default tab (right-click a tab → "Open on start"), stored in settings.
3. **Toolbar**: scope segmented control (Whole model / Active view / Current selection), Include linked files, Export by type; right side: Section box, Isolate, Reset view, Project standards ▾ (Export / Import).
4. **Body — four columns**: Categories (280 px) · Available parameters (*) · move buttons (44 px) · Selected parameters (*). Splitters between columns.
5. **Bottom bar**: live status line, Reset, Preview / Edit, Import ▾ (Excel… / recent files), **Export ▾** (Excel… / Empty template… / Keep formatting… for schedules).

## 2. Colour coding (the core of the look)
Every parameter row (Available and Selected lists) is tinted by kind, with a 3 px left border in the stronger tone and a kind glyph:

| Kind | Row fill (light / dark) | Border + glyph (light / dark) | Glyph |
|---|---|---|---|
| Instance | `#E4F4EA` / `#203A2C` | `#3E9A66` / `#5CC48A` | filled square |
| Type | `#FFF3D3` / `#3D3320` | `#B7841A` / `#E0B04A` | small tree (type → instances) |
| Read-only | `#FBE4E4` / `#3F2627` | `#C2514E` / `#E07B78` | filled circle |
| Selected row | `#CFE5FA` / `#1F3550` | `#2F7FD0` / `#5AA3EE` | – |

- A read-only **type** parameter shows as Read-only (red) with a small "T" overlay on the glyph.
- Shared parameters get a small `SHARED` tag (blue outline); project parameters `PROJECT`; built-in no tag.
- The workbook and the Preview / Edit grid use the **cell palette** in 04_EXCEL_FORMAT §3 (editable instance cells unfilled, type yellow, read-only red, missing dark grey).

## 3. Legend chips = filters
Under the Available list: three chips **Instance n · Type n · Read-only n** (counts live). Click toggles visibility of that kind (chip greys out). Ctrl+click = show only that kind. Double-click a chip = add all visible parameters of that kind to Selected.

## 5. Preview / Edit tab
- WPF `DataGrid` with virtualization (`EnableRowVirtualization`, `EnableColumnVirtualization`), frozen fixed columns (Id, Category, Family, Type).
- Cells use the same kind colours (no left border); read-only and missing cells are not editable.
- Edited cells get a **bold value + dot marker**; header shows "n edits".
- Buttons: **Apply to model** (goes through the same Diff → Changes window → Apply path as import), **Export…**, **Discard edits**.
- Filter row above the grid (per-column text filter) and a "Show only edited" toggle.

## 6. Other windows
- **Changes preview** (03 spec) — reuse kind colours for the Parameter column; status icons ✓ ⚠ ✗; footer counters.
- **Export options** — card-style dialog: destination file, layout (one sheet per category / single sheet), options (Instructions sheet, protect read-only cells, open after export), existing-sheet handling.
- **Progress** — inline in the title-bar chip for short work; modal-less progress window only for > 3 s operations, with Cancel.

## 7. Implementation notes (WPF)
- Put all colours in `UI/Theme/Colors.Light.xaml` and `Colors.Dark.xaml` (same keys); swap the merged dictionary at runtime for theme changes. Remove the single `Theme.xaml` colour block or make it reference these.
- Row tint: `DataTrigger` on `ParamRow.Kind` (`Instance|Type|ReadOnly`) in an `ItemContainerStyle`; glyphs as `Path` geometries in `UI/Theme/Glyphs.xaml`.
- Lists can be large (300–800 parameters): `VirtualizingStackPanel.IsVirtualizing=True`, `VirtualizationMode=Recycling`; grouping via `CollectionViewSource.GroupDescriptions` with `IsVirtualizingWhenGrouping=True`.
- Custom title bar: `System.Windows.Shell.WindowChrome` (no third-party libs).
- No third-party UI controls (no Syncfusion/DevExpress/Telerik) — licence-free.

## 8. Interaction details (confirmed against the public docs, Nov 2026)
- **Collapse/expand:** double-click the title bar collapses the window to its title bar (keeps it open while working in Revit); double-click again restores. Remember state.
- **Minimum size:** 1000×640; content never clips below that.
- **Multi-select** in every list: click, Shift+click (range), Ctrl+click (toggle). All add/remove/move actions apply to the whole selection.
- **Double-click or drag-drop** a parameter between Available and Selected adds/removes it; drag inside Selected reorders.
- **Sortable columns:** clicking a list column header (Name, Data type, Coverage) sorts A–Z / Z–A; numbers numerically.
- **Row context menu (right-click):** parameters → Add / Remove / Copy name / Copy GUID / Show elements missing it; categories → Check only this / Select elements in model / Isolate; schedules → Open schedule; rooms/spaces → Highlight in model.
- **Section box** (toolbar): uses the active 3D view or a duplicate (user choice in a small popup), offset in project units, option "only selected elements visible".
- Every action that changes the Revit view (isolate, section box, highlight) has an undo-friendly **Reset view** next to it.

## 9. Refinements from reference screenshots (user-provided, Nov 2026)
Behaviour to match (in our own visual style):

**Preview / Edit tab** — a spreadsheet view of exactly what will be exported:
- Excel-like grid: column letters (B, C, D…) and row numbers (data starts at row 3), so a cell reference in the app equals the one in Excel. Hidden mapping row/column are not shown.
- **Header cell = 4 lines**: parameter name (bold) / storage-data type ("Length", "Text", "Element", "Yes/No") / kind ("Instance", "Type", "Fixed") / parameter group ("Dimensions", "Other"), plus a filter drop-down button per column (value list with checkboxes + text search, like Excel autofilter). Header background = our accent colour, white text.
- Cells use the **Excel cell palette of 04 §3**: editable instance = no fill, editable type = yellow, read-only = red, missing = dark grey; fixed columns frozen. (The parameter *picker* lists keep the green/yellow/red row tints of §2.)
- **Worksheet tabs at the bottom**: one per category/schedule + `Instructions` + "+" is *not* needed (sheets come from the export selection). Scroll arrows when tabs overflow.
- Bottom-right buttons: **Reset** (discard edits) and **Update model** (primary; runs Diff → Changes window → Apply).
- Title-bar progress chip shows detailed progress while the preview is built: `[1/1 sheets] Reading values · 1/1 categories · 2 665/2 665 elements · 100 %`.

**Instructions sheet** (in Excel and in Preview): a small legend table (fill swatch + description: Type value / Read-only value / Parameter does not exist for this element / Linked element) and a Note about keeping type values identical for all elements of the same type. Write our own wording; add our extra rules (hidden row/column, Find & Replace hint).

**Export options** — small popup anchored to the Export button (not a full dialog):
- Options: *Keep schedule formatting* (enabled only on the Schedules tab; tooltip "not importable"), *Open file after export*, *Include Instructions sheet*, *Protect read-only cells*.
- Destination buttons: **Excel** (and Google, greyed "coming in v2"). A ★ on a destination makes it the default so the main Export button exports there directly; ▾ opens the popup again.

**Import ▾ menu**:
- *Import from Excel…* — file picker → Diff → Changes window → Apply.
- *Preview import…* — file picker → loads the workbook into the **Preview / Edit** tab (edited cells marked) so the user can review/adjust in-app, then **Update model**.
- *Import from Google* — v2, hidden until implemented.
- Recent files (last 5).
